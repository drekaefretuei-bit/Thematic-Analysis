# Step-by-step explanation of the Python extraction code

The Python script was used to convert a folder of full-text article files into structured study-level datasets for review analysis. The script processes text files rather than PDFs directly. This reflects a two-stage workflow in which the articles are first converted into machine-readable text and then analysed using rule-based extraction. The purpose of the code is to generate comparable fields for each study, including article ID, study title, research focus, theory, study design, data-collection period, sample size, geography, methodology, sample characteristics, key variables, findings summaries and verbatim finding quotes with page references.

First, the script defines the input and output locations. The input folder is named `SLR Text Articles`, and the outputs are saved as both Excel and CSV files. Two datasets are produced: a detailed file containing all extracted fields and a shorter summary file containing the main review fields. The filenames end with `TEXT`, making clear that the extraction was conducted from text files.

Second, the script sets up dictionaries and keyword lists that guide the extraction. These include section headers such as abstract, introduction, methodology, sample, results and conclusion; study-design terms such as panel data, fixed effects, regression, content analysis, text analysis and mixed methods; board-diversity terms such as gender diversity, female directors, ethnic diversity and intersectionality; and disclosure-outcome terms such as narrative disclosure, readability, tone, impression management, sustainability reporting and ESG disclosure.

Third, the script includes a theory-detection dictionary. This searches for theoretical lenses such as agency theory, stakeholder theory, legitimacy theory, institutional theory, resource dependence theory, upper echelons theory, signalling theory, critical mass theory, feminist theory and intersectionality theory. When a theory is found, the script records both the theory label and supporting evidence sentences from the article text.

Fourth, the script reads each article text file. It normalises the text by removing unusual characters, fixing common ligature problems and reducing irregular spacing. It also removes the reference list before analysis by cutting the text at the “References” heading. This is important because it reduces the risk that theories, findings or keywords from cited studies are incorrectly attributed to the current study.

Fifth, the script attempts to preserve page-level information. If the text file contains page breaks or page markers, the script separates the article into page records. These page records are later used to attach page numbers to verbatim findings. This supports traceability because extracted finding quotes can be checked against the original article pages.

Sixth, the script identifies the article title. It first searches the opening lines of the full text for a plausible title. If no suitable title is found, it uses the text filename as the study title. The filename is also retained as the article ID, ensuring that every extracted row can be linked back to the source file.

Seventh, the script splits the article into broad sections. It recognises common headings such as abstract, introduction, methodology, sample, results and conclusion. These sections are then used to target different extraction tasks. For example, research focus is extracted mainly from the abstract and introduction, while methodology and sample characteristics are extracted mainly from the methodology and sample sections.

Eighth, the script extracts the study design. It searches the methodology-related text for design patterns such as panel data, regression analysis, fixed effects, random effects, logistic regression, difference-in-differences, content analysis, automated text analysis, survey, interview, qualitative, quantitative and mixed-methods study. If no design pattern is found, the field is recorded as “Not specified”.

Ninth, the script extracts the data-collection period, sample size and geography. It identifies year ranges such as “2016–2020” or “from 2016 to 2020”; sample expressions such as “500 firms”, “1,000 firm-years” or “74 articles”; and country or index terms such as United Kingdom, United States, China, India, Nigeria, FTSE, S&P, NYSE and STOXX. These fields help standardise the descriptive characteristics of the reviewed studies.

Tenth, the script extracts the research focus and key variables. It searches for sentences containing board-diversity and disclosure terms. The key variables field identifies both diversity measures, such as gender diversity, female directors, ethnic diversity and intersectionality, and outcome measures, such as narrative disclosure, readability, tone, sustainability reporting, ESG disclosure and impression management.

Eleventh, the script extracts key findings. It gives priority to sentences in the results and conclusion sections and uses finding-related phrases such as “our findings”, “our results”, “we find”, “the results show”, “the findings suggest” and “this study shows”. This design helps capture findings from the current study rather than general statements about prior literature.

Twelfth, the script scores and selects verbatim finding quotes. Sentences receive higher scores when they contain current-study finding phrases, board-diversity terms, disclosure terms, intersectional terms, and words indicating empirical effects such as significant, positive, negative, associated, influence, impact, increase or decrease. Sentences are penalised when they appear to refer to prior literature, for example through phrases such as “previous studies”, “prior research”, “according to” or “et al.”. The script retains a maximum of 10 quotes per article and records the page numbers where those quotes appear.

Thirteenth, the script builds one structured row for each article. Each row contains the article ID, study title, research focus, theory, study design type, data-collection period, sample size, geography, methodology, sample characteristics, key variables, key findings summary, verbatim finding quotes and quote pages. Missing values are filled with “Not specified” so that the dataset remains complete and easy to inspect.

Finally, the script saves the outputs. The detailed dataset is saved as `appendix_iii_with_quotes_TEXT.xlsx` and `appendix_iii_with_quotes_TEXT.csv`. A shorter summary dataset is also saved as `appendix_iii_summary_with_quotes_TEXT.xlsx` and `appendix_iii_summary_with_quotes_TEXT.csv`. The detailed file supports auditability and manual checking, while the summary file provides a more concise dataset for reporting and review synthesis.

Overall, the script operationalises the machine-assisted full-text extraction stage of the review. It does not replace researcher judgement; instead, it provides a reproducible data-reduction process that organises unstructured article text into comparable fields. The extracted outputs can then be manually checked against the original articles and used for descriptive analysis, topic modelling and thematic synthesis.
